# 自然语言接入面 —— 设计与论证

2026-09-02 立，基线 `b35c618`。这是**答辩材料**，不是 API 文档：讲的是这一层
为什么长成这样、为什么**故意**不做得更聪明。字段与接口的权威定义在各轨代码里，
本文不复述。

一句话：**人在房间里说人话，系统听懂并把它翻成结构化动作；但真正生效的那一下，
仍然必须由人显式发出。**

---

## 1. 为什么今天在房间里说话没反应

现状是两件事叠在一起，缺一件都不会这么彻底：

| 原因 | 具体是什么 | 后果 |
| :-- | :-- | :-- |
| 房间里没有常驻监听 | `hiclaw/room_demo.py` 是一次性进程：跑完那一条审批就 exit 0 | 演示进程退出后，房间里说什么都没人听 |
| 只认两个词 | 命令解析是前缀匹配 —— `/approve <task_id>` 与 `/reject <task_id> [原因]`，其余一律不理 | 「同意」「批了吧」「这个先别过」全部石沉大海 |

还有第三层，它不在代码里、在客户端：Element 会把 `/approve …` 当成**自己的**
斜杠指令吃掉，弹「未知指令」对话框，人不点「作为消息发送」这条命令根本没离开客户端。
这一条与本层无关，但演示当天最先撞上它 —— 处置写在 `docs/matrix-room-runbook.md` §4。

三层加起来，用户看到的现象是同一个：**说了话，什么都没发生**。而这三种「没发生」
在房间里长得一模一样。自然语言接入面要修的是前两层。

---

## 2. 这一层买什么，不买什么

**买两样：少打字、看得懂。**

- 少打字：人说「同意，把那个批了吧」，不用去卡片里逐字复制 12 位 hex 的 task_id
- 看得懂：认不出的时候机器人**说人话解释自己认不出**，而不是一声不吭

**不买的那一样，是全文的重点：不买「替人做决定」。**

自然语言层的输出永远只有两种进程内数据 —— 一个表示「我理解成了什么」的意图对象，
一个表示「所以我要回房间说什么」的派发结果。它**不调用审批队列、不写状态、
不进事件契约、不落库**。整条链路上，能让一个任务从 BLOCKED 走到 DONE 的入口，
今天是什么，加了这一层之后**一字不差还是什么**。

## 3. 🔴 为什么自然语言不能直接授权

这一节是设计的核心，也是最该被追问的地方。

**结论：自然语言不能直接授权，它只产出一张确认卡片；显式指令仍是唯一生效入口。**

房间里的形态是这样的 —— 人说人话，机器人回一句确认，人再发一次显式指令：

```text
人：  同意，把刚才那个批了吧
机器人：你是想批准 task_997ca4541e66 吗？确认请发：/approve task_997ca4541e66
人：  /approve task_997ca4541e66
机器人：已批准 task_997ca4541e66（操作人 @boss:maos.local）
```

### 3.1 论证

模型（乃至关键词匹配）**判断错一次，等于越权批掉一笔生产变更**。而这类错误有三个
让它格外危险的性质：

1. **不可逆**：审批放行之后，补丁已经合进生产，撤销要走另一条更贵的路
2. **无声**：错批与对批在房间里长得完全一样，没有任何异常可看
3. **像对的**：模型很擅长编出**格式完全正确**的 task_id、很擅长把「这个先别过」
   读成同意 —— 错误不以乱码的形式出现，而以一个合理的句子出现

所以把「理解」和「授权」拆成两步：**理解可以错，授权不许错。**
理解错了，代价是人多看一眼那张确认卡片、发现认岔了、重说一遍；
授权错了，代价是一笔没人批准过的生产变更。这两个代价不在一个数量级上，
所以它们不该共用同一条路径。

### 3.2 这不是能力不足的妥协

会被问到的一句是：「模型都这么强了，为什么不让它直接批？」

答案不是「怕它不准」，而是**准也不给**。哪怕解析准确率是 100%，这道闸也要留 ——
因为审批这个动作的意义**不在于判断对不对，在于有一个人对它负责**。
一条由推断产生的放行，事后没有任何人可以说「这是我批的」。
把闸门从「谁能判断对」挪到「谁按了那一下」，是这一层刻意的设计，不是能力上限。

### 3.3 顺带挡住的两件事

同一道闸还免费挡住两个具体的坑：

- **编 task_id**：解析出的 task_id 必须命中调用方给的已知任务列表，对不上一律降为
  「认不出」。模型编 id 的成功率很高，命中真实任务列表的成功率很低
- **旁人代批**：确认卡片不看发言人，真正生效的显式指令才过审批人名单。
  于是「谁都能说人话，只有名单里的人能授权」

## 4. 与铁律 8 的关系

铁律 8 说的是：**MAOS 不持有权威事实，只持有观察与推断。**
订单、支付、库存的权威状态永远归属外部系统，任何把外部状态直接写死为终态的代码
都是 bug。

本层是同一条原则换了个面：

| | 铁律 8（对外部系统） | 本层（对人） |
| :-- | :-- | :-- |
| 什么是观察/推断 | 外部系统回给我们的响应、超时、重试结果 | 模型对一句人话的理解 |
| 什么是权威 | 外部系统自己的状态 | 人显式发出的那条指令 |
| 禁止什么 | 把推断出来的外部状态写死成终态 | 把推断出来的意图直接执行成授权 |
| 允许什么 | 记录观察、发起动作、等权威回话 | 记录理解、给出确认、等人回话 |

一句话：**权威动作不能由推断产生。** 铁律 8 管的是「外部世界的事实不归我们定」，
这一层管的是「人的决定不归我们代做」。两者是同一句话在两个方向上的应用 ——
所以这一层不是新加的规矩，是既有原则的自然延伸。

铁律 9 也在这里落地：本层**不在状态机里加任何状态或迁移**。
「等人确认」不是一个新的任务状态 —— 它压根不进库，只是机器人在房间里说的一句话。
需要新状态才能表达的设计，说明抽象错了。

## 5. 三条红线的落地形态

| 红线 | 落地成什么 | 破了会怎样 |
| :-- | :-- | :-- |
| R1 自然语言不授权 | 解析出 approve / reject 时，派发结果**只许是「确认」这一种**；调用审批队列的唯一入口仍是显式指令文本 | 一次幻觉 = 一笔越权放行 |
| R2 task_id 不许由模型编 | 解析出的 task_id 必须命中已知任务列表，对不上一律降为「认不出」 | 机器人会去批一个不存在或不该动的任务 |
| R3 不碰状态机与冻结面 | 不加状态、不加迁移、不改冻结契约、不新增表；两种输出都只在进程内活着 | 冻结面被击穿，整轨作废 |

R1 有一条**机器自证**：`scripts/nl_smoke.py` 在三个模块都合并之后，会把一句人话
走完全程，并断言 approve 意图的派发结果是「确认」而非「已执行」——
不是的话它退 1。这一条做过变异检验：把派发结果改成「已执行」，脚本立刻退 1。

---

## 6. 怎么自己看一眼

```sh
python3 scripts/nl_smoke.py; echo $?
```

- **exit 3**：三个模块还没合并齐，脚本会打印缺的是哪几个。这是**预期**，不是失败
- **exit 0**：跑通了端到端，逐步打印「人说的话 → 解析出的意图 → 派发结果」
- **exit 1**：合并了但坏了 —— 最要紧的一种是 R1 被破

退出码 3 与 1 分开是有意的：「还没合并」与「合并了但坏了」必须一眼能分开，
否则整合期天天在看假红。

这份冒烟**不打网络、不连房间**：模型走强制 scripted、总线走进程内。
在没有任何 key、没有 Synapse 的裸机器上必须能跑 —— 跑不了就是它自己坏了。

## 7. 已知不做的事

写在这里是为了答辩时能直接回答「为什么没做」，而不是现场想：

- **不做多轮对话**：机器人不记上一句。「批了吧」这种缺 task_id 的话，
  一律回确认卡片让人补全，而不是从上下文里猜是哪个任务 —— 猜错的代价见 §3
- **不做自动执行低风险审批**：没有「小改动可以让模型直接批」这一档。
  风险分级决定的是**要不要人批**，不是**谁来批**
- **不把理解结果落库**：意图与派发结果都是进程内数据。落库就等于给推断
  发了一张事实的身份证，与铁律 8 冲突
