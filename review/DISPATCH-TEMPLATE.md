# 派单模板（MAOS 多轨并行）

从 C-1..C-4 / D-1 / D-2 / E-1 / E-2 / F-1 九份实际派单里抽出来的共性骨架。
落成模板的直接起因：**派单从来没告诉子会话「哪些拦截是预期的」**，
于是一次纯只读查询触发一次假警报（见 §3）。

用法：整段复制「二、模板正文」，把 `<尖括号>` 占位换成当轮实测值。
**§3 是固定条文，逐字照抄，不要删改** —— 它每轮都一样，删了就回到假警报。

---

## 一、给编排侧的四条使用须知

1. **易腐值一律只写进 §0**。基线 sha、`N passed` 条数、「某轨尚未合并」这类状态
   隔几小时就不对了。散落全文就刷不干净，子会话开场自检第一条对不上，
   会把它当成回归报假警。
2. **粘之前 grep 一遍**旧 sha / 旧条数：抬头、§0、时序说明、§6 验收命令、
   §7 回执格式里的都要一起刷。
3. **建完 worktree 先在其中一个里实跑一次**测试与入口脚本，把条数和 exit code
   写进 §0。只认可复现的输出，不认自述。
4. **启动命令里 `cd` 必须和 `claude` 写在同一行**：

   ```
   cd ~/Documents/MAOS/.worktrees/task-<轨号> && claude "$(cat ~/Documents/MAOS/review/paste-<轨号>.md)"
   ```

   先起 `claude` 再 `cd` 会让守卫 hook 静默失效 —— `CLAUDE_PROJECT_DIR` 在进程启动
   那一刻定死，而 hook 执行失败是**非阻塞放行且不报警**。所以 §1 末条的守卫自检
   要子会话去 Read 守卫脚本，**被拦才算 hook 挂上了**。

````markdown

基线钉 `<分支>` 的 HEAD `<sha>`。<若不是主干，写清为什么钉这里>
同期并行 <轨号列表> 共 <N> 轨，**与你零文件交集**，除两份账本的尾部追加。

- `python3 -m pytest maos/tests -q` → **<N> passed**，exit=0

- <本轨相关的其它基线读数，逐条写实测值>

- <某项> 因 <原因> 现在是 <现象>，**不是你搞坏的**。

### 0.2 范围裁剪（可选，来源是多条清单时才写）

<把「这条已完成 / 这条归别人 / 这条已被别的轨持有」逐条写死，
免得子会话去重做已经做过的事、或去动别人正持有的文件。>

| 原清单条目 | 实测结论 | 谁的事 |
| :-- | :-- | :-- |
| <条目> | <✅成立 / ❌已完成 / ⚠️部分完成，附行号与出处> | <本轨 / 某轨 / 等某轨合并后另开> |

## 1. 工作区与开场自检（<N> 条，不许动任何文件）

```bash
cd ~/Documents/MAOS/.worktrees/task-<轨号>
git log --oneline -1                      # <sha>
git status --porcelain                    # 0 行
git rev-parse --show-toplevel             # 必须以 /.worktrees/task-<轨号> 结尾
python3 -m pytest maos/tests -q           # <N> passed
python3 run.py > /dev/null; echo $?       # 0
<本轨相关的其它自检命令 + 期望值>
```

最后一条是守卫自检：**用 Read 工具读 `scripts/guard_bash.py`** → **被拦**
（报 `blocked: 该操作触碰受保护面`）才算 hook 挂上了；
**读到内容 = 守卫没挂上，停下来报告，不要继续** —— 最常见原因是会话不是从
worktree 根启动的（项目级 hook 只在仓库根加载）。

对不上任何一条：停手，把实际输出贴回来，不要自己往下推。

## 2. 身份与红线

- 你是 <轨号> 轨。**只许本地 commit，禁止 push / rebase / checkout / pull /
  建新 worktree / 动别的 worktree。**
- `git add` **逐文件点名**，禁止 `git add -A` / `git add .` / `git commit -a`。
- 提交格式：`<feat|fix|docs>(p<N>): <一句话>`。
- 本机**没有 `python` 命令**，一律 `python3`。
- **铁律 4**：白名单外的问题记进 `docs/BACKLOG.md` 尾部**另起** `## task-<轨号>` 小节，
  **不要顺手修**。
- **铁律 7**：自行做的判断 / 口径选择记一行进 `docs/DECISIONS.md`。
- 守卫禁改面：`maos/contracts/**`、`scripts/guard_bash.py`、`.claude/**`、
  `.contracts.lock`、`docs/parallel/contracts.md`、`maos/artifacts.py`。

## 3. 🔴 守卫的预期拦截清单（固定条文，每轮照抄）

守卫（PreToolUse hook）拦掉对受保护面的**只读**引用是**设计意图**，不是 bug。
`scripts/guard_bash.py` 文件头写着「契约文件允许 Read，守卫脚本与本配置不允许 Read」；
§1 末条的自检更是**依赖**这个拦截 —— 被拦才证明 hook 挂上了。
**不要去放宽守卫，也不要为了绕开它改写守卫。**

### 3.1 判据：预期拦截 vs 异常拦截

| | 预期拦截 | 异常拦截 |
| :-- | :-- | :-- |
| 长什么样 | 命中受保护路径 / 裸文件名的**只读**引用；以及 §1 那次 Read 自检 | 你在动**自己白名单内**的文件却被拦 |
| 怎么办 | **换个写法继续**（见 3.2），记进 §7 回执的「被守卫拦过吗」 | **停手报告人类**，不要绕、不要试第二种绕法 |

守卫的报错末尾会告诉你是哪条规则命中的，据此选招式：

- `…（读取位置）` → 命中的是路径 / 裸文件名位置判定 → 走 3.2
- `…（不透明载荷）` → 命中的是 3.3 那张反面清单 → 先把不透明构造去掉

### 3.2 换个写法的五招（都可以直接抄）

1. **查受保护文件的历史** —— 别 `git log -- <受保护路径>`，改看全局或直接问人类：

   ```bash
   git log --oneline -5                      # 放行
   git log --oneline -- scripts/guard_bash.py   # ❌ exit=2
   ```

2. **查自己的禁改面** —— 别 grep 那些裸文件名。禁改面清单已经写在本派单 §4，照着读就行：

   ```bash
   grep -rn guard_bash.py review/            # ❌ exit=2（裸名也命中）
   ```

3. **写含受保护路径字面量的文档** —— **用 Write / Edit 工具**，不要 heredoc。
   守卫对 Edit/Write 只看 `file_path`，`content` 一律不看；
   而 `cat > file <<EOF` 是 Bash 命令，正文会被分词命中。

4. **多行 commit message** —— Write 落临时文件再 `-F`；单行直接 `-m`。
   commit message 里同样别出现受保护的裸文件名：

   ```bash
   git commit -F /tmp/commit-msg.txt         # 放行
   ```

5. **需要确认某条命令会不会被拦** —— 跑探针，别去猜、也别用 `python3 -c` 试
   （`-c` 会命中 3.3，探针自己先被拦）：

   ```bash
   python3 review/tools/guard_probe.py                  # 内置样例
   python3 review/tools/guard_probe.py '<一条命令>'     # 探自己的命令
   python3 review/tools/guard_probe.py --file cmds.txt  # 含受保护裸名时只能走这条
   ```

### 3.3 反面清单：这些一旦与受保护名同现，必被拦

`$(...)` ／ 反引号 ／ `eval` ／ `base64` ／ `awk` ／ `source` ／ `<<<`

守卫遇到它们就**放弃位置判定，改对整条命令做子串扫描**。此时哪怕是纯只读上下文，
只要受保护的字面量出现在命令里就拦，报 `（不透明载荷）`。

### 3.4 🔴 最反直觉的一条：三个裸文件名不写路径也会命中

`guard_bash.py` ／ `relock_contracts.py` ／ `.contracts.lock`

**裸文件名就足以命中，不需要写全路径。** 所以 `grep guard_bash.py …`、
`echo relock_contracts.py`、`cat .contracts.lock` 全都会被拦，
报错里守卫还会把裸名补成完整路径（`scripts/relock_contracts.py`）。
````

## 三、模板自检

新写一份派单，粘之前对着过一遍：

- [ ] 抬头有**完整 sha**，不是分支名（别的会话可能正在推进主干）
- [ ] 所有易腐值都在 §0，正文里没有第二处写死的 sha / 条数
- [ ] §0.1 写清了「哪些验收项跑了会红、那是预期」
- [ ] §1 末条是守卫自检，且写明**被拦才算挂上**
- [ ] §3 整节逐字照抄，一条没删
- [ ] §4 的只读表标出了**每个文件当前被哪一轨持有**
- [ ] §5 每条都附了编排侧实测的**原始输出**，并写了「不许照抄结论」
- [ ] §6 有可整段复制的命令块 + 能勾的硬判据
- [ ] §7 回执含「被守卫拦过吗」一栏
- [ ] 启动命令 `cd` 与 `claude` 同一行，路径写绝对路径
