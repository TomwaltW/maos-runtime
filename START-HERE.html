MAOS · 多 Agent 协作运行时

一条退款，从客户投诉
到钱有没有到账。

一条制造企业的售后退款诉求 —— 客户报修一批轴承，说货有质量问题， 要求退 6800 元 —— 由受理、政策、财务、支付几个 Agent 接力完成。 每一步都留下了可以被外人重放核验的证据：谁在什么时候做了什么、 卡在哪一道闸、哪一步等了人、外部系统到底怎么回的。

看完整链路 → 一页离线报告，17 束证据全在里面。现在就能点开，不用装任何东西。 想自己跑一遍？ 可选，见本页最后一节。需要 Python 3.10+，约 7 秒跑完。

报告是一个单独的 HTML 文件，不连网、不读数据库、不引一个外部文件 —— 断网的会议室里照样打开。页面上每个数字都能在 evidence/ 里逐字找到出处。

这套东西想解决的三件事

下面每一条都不是主张，是这个包里可以逐条去查的读数。

结论 01

「Agent 都回复完成」
不等于业务成功

场景 7 里，支付 Agent 两次提交结果说自己做完了。 第一次被闸打回返工，第二次转人工，主管驳回 —— 任务终态 FAILED，整个 Plan 终态也是 FAILED。 系统没有因为每个 Agent 都交了活就判这单成功。

出处 evidence/scenario-7/result.json · 报告「场景 7 → 状态迁移时间线」那条泳道

结论 02

权威事实
不在我们的库里

退款到没到账，权威在支付网关。场景 7 里发起、改派备用渠道都试过了， 网关始终没给出到账终态，于是 系统一条终态都没写 —— 两条网关观察全是 failed，settled 观察 0 条。 后来是人到渠道后台查实、把线下凭证交回来，案子才标 compensated。不猜，不推断。

出处 evidence/scenario-7/business-objects.json · docs/authoritative-facts.md

结论 03

换一个业务域
内核零改动

同一个内核既跑软件交付，也跑退款、保险理赔、银行差错、应付账款。 接这三个新域的提交，对 contracts/、core/、runtime/ 的改动 逐条比对下来全是空的。换域只换业务技能与外部接口。

出处 docs/domain-portability.md §1.1 （三条 git diff --stat 命令，输出均为空）

两条去处

① 看完整链路 → 主入口。双击即开，不需要 Python、不需要网络。 ② 技术方读代码 → 架构、契约、每一项核验的判据都在 README 里。

③ 自己跑一遍（可选，需要 Python 3.10+）

上面那份报告是我们这边跑出来的。你也可以在自己机器上重跑一遍， 看跑出来的是不是同一套数 —— 这一步纯属可选，不做也不影响上面两条。

  1. 回到刚才解压出来的那个文件夹（就是本页所在的这一层）；
  2. macOS 双击 RUN-ME.command，Windows 双击 RUN-ME.bat；
  3. 它会自己检查 Python、跑完 7 个场景、把证据重新生成一遍，再逐项核验。 全绿就是 RESULT: 10/10 PASS。

为什么这里不是一个可以点的链接： 浏览器点本地的 .command / .bat 只会下载或者直接拦掉， 不会运行它。要在文件夹里双击才行。
机器上没有 Python 3.10+ 的话这一步会提示你，不会跑到一半留下半截东西； 装 Python 不是看这个包的前提条件。
