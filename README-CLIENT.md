# MAOS 使用说明（客户版）

这是一套让多个 AI 助手协同办完一件业务的系统。它的特别之处不是跑得快，而是
**每一步都留下了能被外人重新核对一遍的记录**。本文写给第一次拿到这个包的人，
不需要技术背景；要读代码、核对证据，请看 [`README.md`](README.md)。

## 一、三步看到效果

1. **解压**压缩包到任意文件夹，桌面就行。
2. **双击 `START-HERE.html`**。浏览器会打开一个页面，里面是系统办过的事和留下的记录。
   **不用装任何东西**，不用开终端，不用敲命令。
3. **（可选）双击 `RUN-ME.command`（macOS）或 `RUN-ME.bat`（Windows）**，让它在你
   自己的电脑上真跑一遍，跑完会输出一份逐项核验结果。这一步需要电脑上有 Python，
   不做也不影响看效果。

## 二、它解决的是什么问题

先看它处理一笔退款是什么样子。

> 一位客户报修一批轴承，说货有质量问题，要求退款 6800 元。这个诉求同时来自三个地方：
> 工单系统里有一张单、客服聊天记录里提过一次、客户还自己拍了照片发过来。

系统把三处合成同一笔退款，再分派给四个助手各管一段：**受理**合单、**政策**判能不能退
（用的是**下单当时**那一版政策，不是今天改过的版本）、**财务**核算金额、**支付**对接网关。
财务算完之后系统自动查一道：退款金额超过阈值的，必须附上财务核算凭据，缺了就拦死。
这一单凭据是齐的，但金额到了要人拍板的档次——**自动检查全过了也照样停下来**，等主管点头，
放行之后才真的去退钱，最后通知客户。每一步是谁办的、依据是什么，全都留了记录。

### 真正值钱的是失败的那一次

同样这笔退款，换一条路走：支付网关那边出了故障，系统连着问了三次，始终问不出
这笔钱到底退没退成。

这时候四个 AI 助手都已经把自己那一步做完了，都回复「完成」。

**如果系统听它们的，这一单就会被记成「退款成功」——而钱根本没退出去。**

MAOS 没有这么记。它记下来的是：这一单**没有成功**；因为问不出结果，所以「已到账」这个
状态一条都不写；同时自动开了一张人工工单、撤回了退款请求，把这一单交回给人来处理。

> **「所有 AI 都回复完成」不等于「这件事真的办成了」。**

钱有没有到账，权威在支付网关那边，不在这套系统的数据库里。问不出来的时候，它什么都不猜、
什么都不填。这是整套系统的出发点。

（演示用的政策与历史案例是按行业惯例构造的示例数据，不是某家企业的真实政策；
支付网关是对齐公开规范的模拟实现，不会产生任何真实扣款。）

## 四、需要什么环境

- **只看效果**：什么都不需要，任何浏览器都能打开 `START-HERE.html`。
- **想自己跑一遍**：需要 Python 3.10 或更高版本。macOS 一般自带，Windows 可在
  python.org 免费下载。**这一步是可选的。**
- 全程**不联网**，不需要任何账号、密钥或付费服务。

## 五、常见问题

<!-- 待 T149 回执确认措辞：以下两条（Gatekeeper 拦截、chmod +x）的准确步骤以 T149 实测结论为准 -->

**macOS 双击 `RUN-ME.command`，提示「来自身份不明的开发者」打不开。**
右键点这个文件 → 选「打开」→ 在弹出的窗口里再点一次「打开」。只需做这一次。

**提示 Permission denied，或者双击没反应。**
压缩包有时会丢掉文件的可执行权限。打开「终端」，输入 `chmod +x` 再加一个空格，把
`RUN-ME.command` 拖进窗口，回车，然后再双击。

**跑完有几项没通过。**
输出会逐项写明哪一项没过、没过意味着什么。这套系统的立场就是把没办成的事如实记下来，
而不是让它看上去全绿。

**能用在我自己的业务上吗？**
包里演示的是退款，换一个业务域只需要换业务规则那一层，调度和留痕这套内核不用改。
