P3

从一条退款说起

场景价值与复用性 20%

一条真实形态的售后退款诉求，从三处来源进来，走完受理、裁定、核算、放行、支付、通知 —— 每一步都往库里落一个真实业务对象。

客户报修一批轴承，说货有质量问题，要求退款 6800 元。诉求同时来自工单系统、客服聊天记录、客户自拍照片三处。
谁干了什么留下了什么（落库对象）
受理 Agent把三处诉求去重聚合成一个 caserefund_case（submitted）
Manager规划 DAG —— 与软件交付域是同一个 Manager，零改动plan + 5 个 task
政策 Agent按下单时锁定的政策版本裁定退款资格policy_decision
财务 Agent核算退款金额并写财务分录（过第六道闸）finance_entry
支付 Agent发起退款并观察网关回执refund_request + payment_observation

为什么是退款域

它有 MAOS 需要的一切：多源输入、政策裁定、金额核算、外部权威事实（钱到没到账）、 以及一条走不通时的补偿路径。软件自证式 demo 给不出最后两样。

数据口径（先说清楚）

政策与历史案例是按行业惯例构造的合成数据，不是某家企业的真实政策； 支付网关是对齐公开规范的模拟实现。完整口径见 P13。

状态机与七道闸

多 Agent 协同 25% 工程落地与安全审计 30%

全系统只有一个出口能改状态，非法迁移抛异常；产物过七道闸，任何一道有 blocker 就返工。

# maos/core/control_plane.py::_transit # 内部：唯一的状态迁移出口 def _transit(self, task, dst, *, event_id="", …): reason = assert_transition(task["state"], dst) # ↑ 非法迁移抛异常，不静默改写 # ↓ 每一次迁移都落一行 event_log
PENDING → DISPATCHED → RUNNING → AWAITING_REVIEW
→ DONE ｜ BLOCKED ｜ REWORK ｜ FAILED

业务状态不进 Task 状态机

compensated / settled 是 refund_case 自己的字段，不是 Task 状态 —— 上退款域没加新状态、没加新迁移（见 P12）。

第六、七道闸是退款域上线时新增的 —— 但仍领域无关

场景 6 证明到什么，没证明到什么

三条护栏 · maos/kb/guardrails.py::check_all （评委原话拆成的可执行断言，各带一条负例测试）

① 只增不删

可以往 DAG 里补任务，不能删任何一条既有任务。 历史案例里没出现过某一步，不等于这一步不必要 —— 可能只是当时没记全。

② 不替代事实

建议任务不许携带订单事实字段。当前订单事实只能从 order_snapshot 读， 一条都不许从知识层来。

③ 不跳审批

不能移除高风险标记、不能把 effect_risk 降下来、不能带「免审批」标记。 检索到「上次这类单直接放行了」也不行 —— 上次放行是人做的决定。

权威事实边界

工程落地与安全审计 30%

MAOS 不持有权威事实。全系统只有 payment.observe 写得进 settled，且必须同事务附回执 —— 越权抛异常并落证据。

# maos/domain/refund/guard.py::AUTHORITATIVE_STATES AUTHORITATIVE_STATES = frozenset({"settled"}) # maos/domain/refund/guard.py::update_biz_status ③ # ③ 权威终态必须有回执。 # 没有回执的 settled 就是把外部状态写死为终态。 _log_violation(store, …) # ← 落库 raise AuthoritativeFactViolation(…) # ← 抛

越权不静默失败

抛 AuthoritativeFactViolation 并落一条事件。 payment.observe 之外的任何 skill 想写 settled，或写 settled 时没带 observation，两条路都不通。

fail-closed：漏配判据也不放行

加了权威终态却没给回执判据 → 第 ④ 道直接拒。 宁可写不进去，也不许默认放行 —— 否则「有回执」会被当成默认真。

🔴 实况：这个核验器真的抓到过一次绕过

不是「我们从没出过错」，而是 核验器自己抓到了：有一条路径绕过 guard 直接写 SQL， 两轨各自测试全绿、合并后才暴露。

根因、为什么两轨都绿、以及那一行修法，全部写在文档里没有删 —— docs/authoritative-facts.md §4。

一个能自己发现「边界被绕过」的核验器，比一句「我们划分了边界」有说服力得多。
