# 失败姿态 —— 三条判据

**这份文档不改任何行为。** 仓库里这三件事**已经在做对**，但每一条都只活在某个文件的
某段注释里。评审最可能追问的正是这一层 ——「你们知道哪些失败该响、哪些该让路吗？」——
现在答得出，但要现翻六个文件。本文把它收成三句可引用的口径，外加一份五分钟能用完的检查单。

出处：`docs/refs/cumora-data-model.md` §3 #2 / #3、`docs/refs/cumora-coordination.md` §3 #5。
参照实现是 cumora（`server/src/agents/seen-boundary.ts` 的文件头）。

> **行号纪律**：本文**尽量不写行号**。行号会随别人的改动漂移，而一份写着错行号的判据
> 文档比没有更糟。只有三个文件例外 —— `maos/store/pg_store.py`、`maos/kb/guardrails.py`、
> `maos/domain/*/guard.py`，它们是本轮无人改动的取样对象，行号可靠。
> 其余一律只写**文件名 + 函数名**，自己 grep 去。

## 判据一：协调信号 fail-open，正确性不变量 fail-closed

**一句口径：**

> 一个机制坏掉时，如果最坏后果只是**结果变差**（多做一次、排序差一点、少一条提示），
> 它是**协调信号** —— 该 fail-open，绝不能让主流程卡住。
> 如果最坏后果是**结果变错**（钱算错了、越权过去了、假绿盖住了真红），
> 它是**正确性不变量** —— 该 fail-closed，宁可当场停住也不许静默放行。
>
> 判一个新分支属于哪边，只问一句：**它坏掉时，还能不能自证结果是对的？**
> 能 → fail-open；不能 → fail-closed。

两端的标准样本（都无人改动，行号可靠）：

- **fail-open 的样本** —— `maos/store/pg_store.py:58-60` 的模块 docstring 末段：
  `_port_search` 是「探一次记一次」，一次 CJK 查询抛错就把该 store 的全文通道
  **永久**标记为不可用，之后退化走本地实现。原文写着「这是如实的结果，不是缺陷伪装」。
  **检索排序是协调信号：错了结果变差，不会变错。**
- **fail-closed 的样本** —— `maos/kb/guardrails.py:60-62` 的 `GuardrailViolation`：
  docstring 明写「**不要 catch 成告警** —— 这是『知识替代了事实或授权』，与越权调用同级，
  必须中止并留痕」。**这是正确性不变量：错了结果是错的。**

### 现有失败姿态归属表

| # | 位置（文件 · 函数） | 失败长什么样 | 倒向哪边 | 为什么那是对的 |
|---|---|---|---|---|
| 1 | `maos/kb/guardrails.py` · `GuardrailViolation`（`:60-62`） | 检索结果越界：知识层给出的建议超出了它被允许触碰的面 | **fail-closed**（抛，且不许 catch 成告警） | 「知识替代了事实或授权」与越权调用同级 —— 一条越界的建议一旦被当成任务派下去，产出就是错的，且没有任何下游会发现。铁律 8 的直接推论 |
| 2 | `maos/store/pg_store.py` · `_port_search` 的探测（`:58-60`） | PG 没有中文分词器，CJK 查询抛 `LookupError`，该 store 的全文通道被永久标记不可用 | **fail-open**（降级走本地实现，主流程不中断） | 检索排序是协调信号。退化后中文召回仍然是好的，只是不经过 PG —— 结果变差，不会变错。关键是它**如实降级**：不假装「没命中」（那才是把「后端没准备好」伪装成「查了没有」） |
| 3 | `maos/store/pg_store.py` · `PgBackendUnavailable`（`:159`，理由在模块 docstring `:14-22`） | PG 后端连不上库（驱动没装 / DSN 没配 / 库没起） | **fail-closed**（抛，**绝不静默回落 sqlite**） | 与 #2 同一个文件、方向相反，正是本判据最好的对照：**回落一个能用的 sqlite 会让「PG 验过了」变成假话**，而没有任何东西提示你该重验。排序可以退化，「验过了」这个断言不可以 |
| 4 | `maos/tools/sandbox.py` · 容器不可用时的降级 | Docker 探不到 / 镜像没 build / 测试环境强制降级 | **fail-open，但响亮** —— 降级为裸 subprocess，同时把 `sandbox_mode` 与 `degraded_reason` 写进 test_report 一起落盘 | 这一条是 cumora 的**反向**选择（它 `failIfUnavailable: true`），MAOS 仍判 fail-open 是对的：演示现场跑不出测试等于什么都证明不了。但「容器隔离」是提交材料里的一句断言，降级发生时那句断言不成立 —— 所以**降级必须进报告，不能只进日志**。⚠️ 缺一个「宁可不跑也不裸跑」的配置档，已记 BACKLOG，**T47 在改它的留痕方式，方向不变** |
| 5 | `maos/runtime/gate.py` · `_finance_threshold` | 财务复核阈值读不出数（配置面拿不到 / 值解析不了） | **fail-closed 方向的 fail-open**：回落默认阈值并告警，**不抛** | 两层要分开看。**不抛**是对的：Gate 抛异常会掀掉整个 plan，那是拿正确性不变量的姿态去处理一个可以有缺省的旋钮。**回落方向是收严**（默认值通常低于误配的那个大数）—— 宁可多拦一次，也不因为配置写错而漏掉财务复核。⚠️ T48 在改这里的留痕，方向不变 |
| 6 | `maos/runtime/gate.py` · `_over_finance_threshold` | 申报金额解析不出数（`float("六千")` 抛） | **fail-closed**（解析不出即**触发**复核） | 注释原话：「解析不出 = 自证不了它在阈值之下」。吞掉当 0 算的话，一笔字段脏掉的高额退款就悄悄绕过了财务复核 —— 与把 `tool_error` 读成「0 条失败」同类假绿。注意它与 #5 方向一致而机制不同：#5 是旋钮，#6 是被判定的那笔钱 |
| 7 | `maos/model/client.py` · `select_model_client` | 三个 `MAOS_LLM_*` 环境变量缺任何一个 | **fail-open**：降级 `ScriptedModelClient`，只记录**缺失的变量名**（铁律 6：值绝不进日志） | 「没配 key」是本仓库的**常态**（裸 clone 必须能跑），不是异常。降级后走的是确定性脚本，产出是可复现的假数据而非错数据 —— 而且**它自报家门**。⚠️ T47 在改这条的留痕，方向不变 |
| 8 | `maos/core/eventbus.py` · `make_event_bus` / RocketMQ 后端 | 后端名拼错，或 RocketMQ 连不上 | **fail-closed**：拼错的值直接抛 `ValueError`，**绝不回落 `InMemoryEventBus`** | 与 #3 同型。回落的后果是「RocketMQ 后端看起来跑通了」—— 一句假的验证结论。注意方向的**边界**：未设环境变量时返回内存版是**缺省**不是回落（裸 clone 无需中间件），拼错一个字母才是错误 |
| 9 | `maos/domain/*/guard.py` · 权威终态的判据校验（三个域同款，如 `maos/domain/refund/guard.py:327`） | 有人往 `AUTHORITATIVE_STATES` 加了新终态，却忘了配对应的回单/证据判据 | **fail-closed**：落 violation 事件 + 抛，宁可写不进去 | 默认放行会让新终态**静默地**退回到「有回执就算数」，而那正是这一层要修的洞 —— 一个只在加新终态时才触发、且不报警的回归。写不进去有人立刻发现，放行没人会发现（铁律 8） |
| 10 | `maos/core/control_plane.py` · `claim` | Worker 认领失败（状态不对 / 幂等键已消费） | **fail-closed**：返回 `None`，调用方直接不执行 | 这是 cumora 明确的**反向**选择（它认领失败 fail-open，「最坏后果是两个 agent 重复做一次事」），而 **MAOS 是对的**：cumora 重复的是搜一次网页，MAOS 重复的是**同一笔退款被处理两次**（铁律 8）。同一个机制在两个系统里属于不同的类，正说明这个判据必须逐处判、不能按机制名照搬 |

**读表的方法**：新写一个失败分支时，先在表里找形状最像的那一行，再问「我这个的最坏后果，
是那一行的最坏后果吗？」不是的话，它多半属于另一边。

## 判据二：任何与调度游标共享状态的东西，结构上就是不安全的

出处 `docs/refs/cumora-data-model.md` §3 #3。cumora 的原话是：收件箱游标既被用来
「下一步该处理谁」，又被用来「界面上显示读到哪了」时，任何一侧的改动都会静默地改掉另一侧。

**本仓的对应形状只有一处，但它在最要害的位置上 —— `task.state`。**

它同时是两样东西：

- **调度游标**：控制面靠它决定下一步派谁（`dispatch_ready` 挑 `PENDING`、`claim` 要求
  `DISPATCHED`、`_advance` 看依赖任务是不是 `DONE`）；
- **展示状态**：房间卡片与演示脚本靠它显示「现在到哪一步了」。

**现在不咬人**，理由是结构性的而不是运气：单进程、事件总线单线程串行 drain、
DAG 串行推进、没有第二个 worker、房间与控制面在同一个进程里。任何一次读到的
`task.state` 都是当下唯一的那份事实。

**什么时候它会开始咬人** —— 三个条件里任何一个成立就够：

1. **异步审批**：人在房间里看到的卡片是某一刻的快照，而 `/approve` 消费的是**此刻**的
   state。已有的 `assert_transition` 让陈旧批准**响亮失败**而不是静默生效 —— 那是现在
   不出事的原因，但那是**拒绝**，不是**正确**。（同一件事的另一半已记在 BACKLOG。）
2. **多 worker**：两个 worker 同时读到 `DISPATCHED`，一个抢到、一个没抢到，
   而房间此刻正把这个 state 渲染给人看 —— 展示的那份注定是过期的。
3. **房间与控制面异步**（跨进程 / 跨实例）：展示侧要自己缓存一份 state，
   从那一刻起「显示的」与「调度用的」是两份数据，且没有任何东西保证它们一致。

**这条判据现在要你做的只有一件事**：不要**再**往 `task.state` 上挂第二种用途。
需要给展示用的信息（进度、当前经手人、上一次为什么被打回），
让它们成为**业务对象自己的字段或独立的事件**，不要挤进这个游标（铁律 9 是同一句话在
业务状态那一侧的说法）。

## 判据三：fail-closed 的方向必须逐处显式写死 —— 五问检查单

出处 `docs/refs/cumora-coordination.md` §3 #5。起因是基线 `926aa7b` 那次真实事故：
**白名单判据方向写反**。本仓已有的正确做法（阈值读不出回落收严、金额解析不出即触发）
是分散的自觉，不是规程 —— 自觉会在赶工的那一天失效。

**什么时候用**：每当你新写一个「读不出 / 探不到 / 超时 / 解析失败」的分支时。
五个问题，五分钟用完。

| # | 问题 | 不合格的回答长什么样 |
|---|---|---|
| 1 | 这个机制坏掉时，结果是**变差**还是**变错**？ | 「不知道 / 应该不会怎么样」—— 答不出这条就别写这个分支，先去想清楚 |
| 2 | 所以它倒向哪边？**在代码里把方向写成一句话**，不是写成一个默认值。 | 只有 `return 0` / `return None` 而没有一句话说明为什么是这个值 |
| 3 | **倒错了最坏发生什么？把那句话也写下来。** | 「会不太准」—— 太软。要写成「一笔字段脏掉的高额退款会悄悄绕过财务复核」这种能吓到人的具体后果 |
| 4 | 有没有**一条用例钉住这个方向**？（不是钉住「不抛异常」，是钉住「倒向了哪边」。） | 用例只断言「没崩」。方向写反时它照样绿 —— 那条用例守不住任何东西 |
| 5 | 这个默认值/回落值，**会不会让某句断言变成假话**？（「PG 验过了」「容器隔离了」「闸判过了」） | 会，但只写进了日志。**日志不进证据** —— 要么别回落，要么把降级原因跟结果一起落盘（见归属表 #3 #4 #8） |

**第 3 问是这份检查单的全部价值。** 前两问大多数人自然会做；第 3 问逼你把
「倒错的后果」写成人话，而那正是下一个想改这个方向的人唯一会读的东西。

**已知的缺口，别指望这份检查单自动生效**：全仓 `maos/`（不含 tests）现有 **39 处**
「except 之后紧跟 return 一个默认值」的吞掉型分支，其中只有 **7 处**在附近说明了方向。
这个统计本身粗（`_has_column` 这种探测、`_dec` 这种数值解析根本不需要方向说明也进来了），
不足以做成一条门禁测试 —— 详见 `docs/BACKLOG.md` 的 `## task-T50` 小节。
在有更细的判据之前，这份检查单靠人记得用。
